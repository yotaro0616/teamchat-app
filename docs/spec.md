## 本書について

- これは、作ってほしいものを文章にまとめたものです。**設計書ではありません**。どう作るかは、これを読んだうえで決めてください。
- 画面の見た目は、`mockup/` に入っている**モックアップ（画面の完成見本）が正**です。ブラウザで開いて確認してください。

## 1. 背景と目的

20人ほどのソフトウェア開発の会社で、社内の連絡係をしています。

いま、社内のやり取りは個人あてのチャットとメールに散らばっています。「あの件どうなりましたか」と聞かれるたびに過去のやり取りを探し回っていて、探し当てられないことも珍しくありません。新しく入った人が、これまでの経緯をたどれないのも困っています。

そこで、**話題ごとに分かれた場所で会話ができて、あとから探せる**、社内向けのチャットアプリを作ってもらえないでしょうか。使うのは社員だけですが、案件によっては特定の人だけで話したい場面もあります。

---

## 2. 対象利用者

| 利用者 | できること |
|:--|:--|
| 社員 | アカウントを作ってログインし、チャンネルで会話する |
| チャンネルを作った人 | そのチャンネルについてだけ、できることが増える（下記の各機能を参照） |
| ログインしていない人 | 公開APIから、公開チャンネルの内容を読むだけ |

## 3. 機能要件

### 3-1. アカウント

社員が自分でアカウントを作れるようにしてください。名前・メールアドレス・パスワードで登録し、そのあとはメールアドレスとパスワードでログインできれば十分です。ログアウトもできるようにしてください。

ログインの仕組みそのものは、よく使われているやり方で構いません。作り方はお任せします。

### 3-2. チャンネル

話題ごとに「チャンネル」という部屋を作れるようにしてください。チャンネルには**名前**と、**何の話をする場所なのかの説明**を付けられるようにしてください。

チャンネルには2種類あります。

- **公開チャンネル**: ログインした社員なら誰でも中を見られて、書き込めます
- **プライベートチャンネル**: 追加された人だけが中を見られて、書き込めます

チャンネルを作った人だけが、そのチャンネルの名前や説明を直したり、チャンネルを消したりできます。他の人にはできないようにしてください。

**チャンネルを作った人は、そのチャンネルのメンバーになります。**あらためて自分を追加する操作は要りません。

### 3-3. メンバー管理

プライベートチャンネルには、**そのチャンネルを作った人が**メンバーを追加したり、外したりできるようにしてください。追加された人は、その時点から中を見られて、書き込めます。

公開チャンネルは誰でも見られるので、メンバーの追加・削除の操作は要りません。

### 3-4. メッセージ

チャンネルを開くと、そのチャンネルに書き込まれたメッセージが並んでいて、その場で書き込めるようにしてください。誰がいつ書いたのかが分かるようにしてください。

自分が書いたメッセージは、あとから直したり、消したりできるようにしてください。他の人が書いたメッセージは直せません。

- 直したメッセージには、**直したことが分かる印**を付けてください
- **消したメッセージは、その場所に「このメッセージは削除されました」と残るようにしてください。**跡形もなく消えてしまうと、その前後のやり取りが何の話だったのか分からなくなってしまうためです

### 3-5. スレッド

メッセージには返信を付けられるようにしてください。返信は、元のメッセージにぶら下がる形で読めるようにしてください。チャンネルの中に返信が混ざって流れてしまうと、話が追えなくなるためです。

元のメッセージには、**返信が何件付いているか**を表示してください。

### 3-6. 検索

キーワードでメッセージを探せるようにしてください。どのチャンネルの、誰の、いつのメッセージなのかが分かる形で結果を出してください。

**検索結果に出てよいのは、その人が見られるチャンネルのメッセージだけです。**自分が追加されていないプライベートチャンネルの内容が、検索結果から見えてしまうことは絶対に避けてください。

### 3-7. 公開API

社内ポータルなど、別の仕組みからこのアプリの内容を読み取って表示したいと考えています。そのための**読み取り専用のAPI**を用意してください。ログインなしで使えるようにしてください。

用意してほしいのは次の2つです。

- 公開チャンネルの一覧
- 指定した公開チャンネルの、メッセージの一覧

**プライベートチャンネルの情報は、チャンネル名も含めて、いっさい含めないでください。**書き込みや変更ができるAPIは、今回は要りません。

## 4. スコープ外（今回作らないもの）

| 作らないもの | 理由 |
|:--|:--|
| 新着メッセージの自動表示（画面を開いたままで届く） | 今回は画面を開き直して確認できれば十分 |
| 通知（メール・スマートフォンへの通知） | まずは社内で使い始められる形を優先したい |
| 1対1のダイレクトメッセージ | チャンネルでの会話に絞りたい |
| ファイル・画像の添付 | 文章のやり取りに絞りたい |
| メッセージへのリアクション（絵文字を付ける） | 会話ができることを優先したい |
| 未読・既読の管理 | 同上 |
| 管理者による全体管理（利用者の停止、他人のチャンネルの管理） | 運用が固まってから考えたい |

## 5. その他の要件

### 5-1. 入力仕様

文字数の上限は、次のとおりでお願いします。

| 項目 | 上限 |
|:--|:--|
| 表示名 | 30文字 |
| チャンネル名 | 50文字 |
| チャンネルの説明 | 200文字 |
| メッセージ本文 | 1,000文字 |
| パスワード | 8文字以上（上限は決めなくて構いません） |

長すぎる入力や、空のままの送信をどう扱うかは、使う人が困らない形にしてください。

### 5-2. 動作環境

使うのは**PCのブラウザ**です。スマートフォンでの表示は、今回は考えなくて構いません。

### 5-3. 画面・デザイン

- 画面の見た目は `mockup/` のモックアップが正です。まず全画面をブラウザで開いて、どんなアプリなのかを見てください
- ピクセル単位で一致させる必要はありません。**並び・項目・言葉づかい・状態の見せ方**が合っていれば構いません
- 画面に出すアプリの名前は「**チームチャットアプリ**」で統一してください
- 色・字の大きさ・余白・状態（エラー・空・編集中）の決まりは `mockup/design-guide.md` にまとめてあります

### 5-4. 初期データ

社内でお披露目するときに、空の画面では説明ができません。**最初から次のデータが入った状態**で使えるようにしてください。

**メッセージ**

- 「編集済み」の印が付いたメッセージが1件以上
- 「このメッセージは削除されました」と表示されるメッセージが1件以上
- プライベートチャンネルにも数件
