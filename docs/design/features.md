# 機能一覧・今回作らないもの

このファイルは `docs/spec.md` と `mockup/` を突き合わせて作成した。各項目の「根拠」に、仕様書のどの節・どのモックアップ画面から導いたかを示す。

前提: 初期データ（アカウント3つ・チャンネル4つ・メッセージ一式）は機能でも除外項目でもなく、`docs/spec.md` §5-4 の投入要件であり、`acceptance.md` の受け入れ条件で扱う。

## 2. 今回作らないもの

### 2-1. 仕様書で明記されているもの

`docs/spec.md` §4 に列挙されている7項目。そのまま転記する。

| 作らないもの | 理由 |
|:--|:--|
| 新着メッセージの自動表示（画面を開いたままで届く） | 今回は画面を開き直して確認できれば十分 |
| 通知（メール・スマートフォンへの通知） | まずは社内で使い始められる形を優先したい |
| 1対1のダイレクトメッセージ | チャンネルでの会話に絞りたい |
| ファイル・画像の添付 | 文章のやり取りに絞りたい |
| メッセージへのリアクション（絵文字を付ける） | 会話ができることを優先したい |
| 未読・既読の管理 | 同上 |
| 管理者による全体管理（利用者の停止、他人のチャンネルの管理） | 運用が固まってから考えたい |

### 2-2. こちらから提案する追加の除外項目（要確認）

仕様書にもモックアップにも記載がなく、こちらの判断で除外を提案する項目。**自分で決めず**、対応する確認事項（`questions.md`）で可否を確認する。

| 作らないもの（提案） | 除外を提案する理由 | 確認事項 |
|:--|:--|:--|
| パスワード再設定（パスワードを忘れた場合の再発行）、登録時のメール確認 | spec §3-1 はアカウント登録・ログイン・ログアウトのみを要求しており、`login.html`／`register.html` にも該当の導線がない | Q-01 |
| プロフィール編集（表示名・パスワードを本人があとから変更する） | spec §3-1 に記載がなく、モックアップ9画面にも該当の画面がない | Q-02 |
