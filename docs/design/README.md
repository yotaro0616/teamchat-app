# 設計書一式の置き場

このフォルダに、**あなたが作る設計書**を置きます。いまは空です。

仕様書（`docs/spec.md`）とモックアップ（`mockup/`）を読んで設計に落としたものが、ここに揃っていきます。実装が終わったあとも、**実物と食い違ったままにしない**でください。この一式が提出物の中心です。

---

## 置くファイル（7つ）

Tutorial 13 で章ごとに学んだ型が、そのまま1ファイルずつになっています。**ファイル名はこのとおりにしてください**（完成の確認をこの表と突き合わせるため）。

| ファイル | 中身 | 使う型 |
|:--|:--|:--|
| `features.md` | 機能一覧と、今回作らないもの | Tutorial 13 Chapter 2 |
| `questions.md` | 確認事項リストと、返ってきた回答／自分で決めたこと | Tutorial 13 Chapter 2 |
| `screens.md` | 画面一覧・画面遷移図・画面項目定義・入力チェックとメッセージ | Tutorial 13 Chapter 3 |
| `data.md` | ER図・テーブル定義書・CRUD表 | Tutorial 13 Chapter 5 |
| `permissions-api.md` | 権限マトリクス・ルーティング一覧・公開APIの設計 | Tutorial 13 Chapter 4 |
| `behavior.md` | 状態遷移図・代表的な処理のシーケンス図・例外方針 | Tutorial 13 Chapter 6 |
| `acceptance.md` | 機能ごとの受け入れ条件と、テスト観点 | Tutorial 13 Chapter 8 |

---

## 書く量の決まり

**設計書は「多く書いたほうが良い」ものではありません。**あとから読む人（自分を含む）が判断に使える分だけを書きます。書く量を決めることも設計の一部です。

| どこ | どこまで書くか |
|:--|:--|
| **画面項目定義** | **主要な画面だけ**。全画面ぶんは書きません。同じ形の繰り返しになる画面は「◯◯と同じ」で済ませます |
| **シーケンス図** | **代表を1本だけ**。全機能ぶんは描きません |
| **受け入れ条件** | **1つの実装単位（Issue）につき2〜4行**。ここは人があとで1行ずつ確かめる約束なので、増やしすぎると確かめきれません |
| **テスト観点** | **観点だけ**。組み合わせを全部書き出す必要はありません。網羅はテストコードの仕事で、そちらはAIに任せます |
| **クラス図** | **作りません**。LaravelのMVCの形に乗ることを1行決めておけば足ります |

---

## そのほかの決まり

- **図はMarkdownの中にMermaidで書きます**（画像ファイルを置かない）。ER図・画面遷移図・状態遷移図・シーケンス図はすべてMermaidです
- **1ファイルに違う種類を混ぜない**。上の表のとおりに分けます
- 実装中に決めが変わったら、**コードではなくここを先に直します**
- 発展課題に挑むときも、**設計をここに足してから**Issueにします
