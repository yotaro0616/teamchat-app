# 画面（Blade・CSS・JS）の書き方

正本は `docs/design/screens.md` と `mockup/`。`mockup/` は**見た目の正本で、書き込み禁止**。読むだけ。

ピクセル一致は要らない。合わせるのは**並び・項目・言葉づかい・状態の見せ方**。PCのみ（最小幅1280px、レスポンシブ対応しない）。

## 文言を自分で考えない

画面に出す文言・エラー文・placeholder は `screens.md` 4章と `mockup/` の該当HTMLから**一字一句そのまま**写す。言い換えると、設計書と違うものが画面に出る。

- エラー文は**1文・句点なし**（例:「チャンネル名を入力してください」）
- 日時は `2026/08/17 14:32` に固定
- アプリ名は「チームチャットアプリ」
- 全角スペースや中黒（`　·　`）も、モックアップにあるとおりに写す

モックアップの `※` で始まる灰色の注記（`mock-note`）は**見本のための注記**で、アプリの画面には出さない。

## CSS は `public/css/app.css` が正本

**Vite は使っていない。**`resources/css/app.css` は空で、`@vite()` ディレクティブもどこにも無い。Blade は `asset('css/app.css')` と `asset('js/app.js')` で `public/` を直接読んでいる。`resources/` 側を編集しても画面は変わらない。

`public/css/app.css` は `mockup/styles.css` の写し。**アプリ側で足した規則は、ファイル末尾の「アプリ側の追加」の節にだけ**、なぜ足したかのコメントを付けて置く。写した部分に手を入れない。

## 色・寸法・角丸を直値で書かない

CSS変数がある（`--sp-4` `--r-md` `--danger` など）。モックアップに無いクラスを作る前に、`public/css/app.css` に定義済みのものを探す。だいたい揃っている。

## JavaScript は2つの用途にだけ使う

**文字数カウンタの追随表示**と、**それに連動する送信・実行系ボタンの活性/非活性**だけ。

- 画面遷移をJSに頼らない。`PATCH`/`DELETE` は `@method()` のメソッド偽装で送る
- カウンタは `data-counter` / `data-counter-max` / `data-counter-submit` 属性で宣言する。`public/js/app.js` が拾う。ビューごとに個別のスクリプトを書かない
- **「押せない状態にする」対象は決まっている**（投稿欄の送信・メッセージ編集の保存・検索・チャンネル削除の確認）。それ以外のボタン（登録する・作成する・追加する）は常に押せるままにし、エラー文で知らせる

JSを無効にされても壊れないようにする。`disabled` の初期値はサーバ側でも付け、入力チェックはサーバ側でも必ず行う。

## 画面の項目を勝手に増やさない・減らさない

`screens.md` 3章の表が項目の正本。足りないと思っても足さない。条件付きで出す項目（作成者にだけ出すボタンなど）は、**サーバ側でも同じ条件を再確認する**。UIで隠すことは判定の代わりにならない。

## 繰り返す部品は partial に切る

`channels/partials/sig.blade.php`（チャンネルの記号）、`channels/partials/badge.blade.php`（公開範囲のバッジ）、`messages/partials/avatar.blade.php`（頭文字2字のアバター）がすでにある。同じものを別の場所で書き直さない。

ただし**モックアップの構造が違うところでは partial を使わない**。たとえばメンバー管理の見出しは `<h1>` の直下にSVGを置く形で、`sig` partial の `<span class="sig">` で包む形とは別物。合わせるのはモックアップ。

## アバターの色は利用者のIDから決める

その場の並び順で割り当てると、画面ごとに同じ人の色が変わる。`messages/partials/avatar.blade.php` が `$user->id` から決めているので、これを使う。
