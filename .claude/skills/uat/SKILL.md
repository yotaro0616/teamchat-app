# UAT（受け入れテスト）

確かめる受け入れ条件は、次のとおりです。

$ARGUMENTS

受け入れ条件そのものではなく、それが書いてあるファイルの場所を渡されたときは、
そのファイルを開いて、書かれている受け入れ条件を読んでから始めてください。

`AC-2-4` のような番号だけを渡されたときは、`docs/design/acceptance.md` の
1章から、その番号の行を探して読んでください。

## 使う道具

ブラウザを動かすのには Playwright MCP を使います。

## 開くURL

`http://localhost`

## ログイン情報

`docs/spec.md` §5-4 の初期データで固定されている3つを使います。

- 佐藤 太郎 `sato@example.com` / `password`
- 鈴木 花子 `suzuki@example.com` / `password`
- 高橋 健 `takahashi@example.com` / `password`

他人のものは触れない、という条件を確かめるときは、アカウントを行き来します。誰で入るかで見えるものが変わるので、次の関係を押さえてから始めます。

- プライベートチャンネル「採用プロジェクト」の作成者は佐藤 太郎、メンバーは佐藤 太郎と鈴木 花子
- 高橋 健はそのメンバーではない（一覧にもサイドバーにも出ず、検索にも出てこないことの確認に使う）
- 鈴木 花子はメンバーだが作成者ではない（メンバー管理画面を開けないことの確認に使う）

## 報告のしかた

受け入れ条件を1行ずつ、満たしているかどうかと、そう判断した理由を、証拠のスクリーンショットとあわせて報告します。

スクリーンショットは、このフォルダの `uat-shots/` に、どの行のものか分かる名前で置きます。

報告のあと、`uat-shots/` を消してよいかを聞きます。見終わったら消して、リポジトリの中にファイルを残しません。

## この部品の範囲

アプリのコードは直しません。画面を触って報告するところまでです。
