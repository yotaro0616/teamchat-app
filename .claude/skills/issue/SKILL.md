# イシューを立てる

`$ARGUMENTS` は、起票したい機能の要望です。

## 手順

1. 渡された要望を読み、いまのコード（`routes/`・`app/`）と `docs/design/` の設計書を見て、決めないといけないことが残っていないかを確かめます。
   - `docs/design/questions.md` も必ず見ます。状態が「回答なし」「一部回答」の項目は、まだクライアントの答えが無いところです。とくに検索（F-17）と公開API（F-18/F-19）に未確定が集中しています。
2. 残っていれば、先にこちらへ質問します。1つずつ答えを受け取ってから次へ進みます。勝手に決めません。
   - クライアントに確認しないと決まらないことは、`questions.md` に「〜という想定ですが、〜ですか」の形＋こちらの想定を添えて足します。
3. 決まったら受け入れ条件を「〜すると、〜になる」の形にまとめ、`gh issue create` でイシューを立てます。
4. 立てたイシューのURLを報告します。

## イシューの中身

- 概要（何を作るのか、いまは何ができないのか）
- 受け入れ条件（「〜すると、〜になる」の形。チェックボックスの箇条書き）
- 変えないもの

`docs/design/acceptance.md` にそのイシューの受け入れ条件がすでにあるときは、書き直さずに `AC-4-2` のような番号を引きます。実装単位ごとに2〜4行という決まり（`docs/design/README.md`）があるので、そこから増やしません。

受け入れ条件の粒度は、次の4行が見本です。

```text
- メッセージの「返信N件」を開くと、そのメッセージと返信の一覧が見える
- 本文を入れて返信を送ると、一覧に増え、「返信N件」の件数が1つ増える
- 本文が空のままだと、送信ボタンが押せず、返信は増えない
- 自分の返信は消せて、他人の返信は消せない
```

## 書き方

イシューの本文は日本語で書きます。
